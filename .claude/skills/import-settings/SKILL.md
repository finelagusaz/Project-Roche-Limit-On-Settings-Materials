# 設定の取り込み

元の資料を読み、設定資料と突き合わせ、作者に一問ずつ確かめてから書く。推測で埋めない。

## 1. 元の資料を読む

| 資料 | 場所 | 注意 |
|------|------|------|
| SS | `../Project-Roche-Limit-Crossing/NNNN_エピソード名【シリーズ識別子】.txt` | 取り込む候補は `ss_backlog.md` で管理する |
| ゴースト | `~/Library/CloudStorage/Dropbox/00_apps_data/named/ghost_dev/<ゴースト>/` の `memo.txt`、`docs/*.md`（カッシーニは `doc/`） | 古いものは cp932。`python3 -I scripts/read_any.py` で読む |
| ゴースト名・キャラ名 | 各ゴーストの `ghost/master/descript.txt` の `name` / `sakura.name` / `kero.name` | memo の表記より descript を優先する |
| 貼られた資料 | 会話の中 | 作者自身の資料。そのまま設定として扱ってよい |

シェルの設定（surface 番号など）や、テンプレートの readme は取り込まない。

## 2. 設定資料と突き合わせる

- 資料の目立つ語（固有名詞・数値・口癖）を `grep -c` で設定資料と extreme_world.md に当て、すでにあるもの・ないものを分ける
- 載っている人物・用語は、該当箇所を読んで中身を比べる
- 結果を三つに分けて報告する
  - **取り込めるもの**: 設定資料にないもの
  - **食い違い**: 誕生日・名前の表記・性格など、両方に書いてあって中身が違うもの
  - **判断が要るもの**: 世界のどこに属するか、ネタバレかどうかなど

## 3. 作者に一問ずつ確かめる

AskUserQuestion で一問ずつ聞く。まとめて聞かない。作者は質問を歓迎しているので、気になったことは遠慮せず聞く。よく出る問いは次のとおり。

- **食い違い**: どちらが正しいか。両方を時期で書き分けるか、併せて書くか
- **世界の位置**: 地球（年代は決めない）か、サイバースフィアゲートの向こうか、ほかの作品と同じ星か
- **書く場所**: 本文、ネタバレ欄（`<details><summary>ネタバレ注意`）、作者メモのどれか
- **構想段階のもの**: 作者メモに置くか、取り込まないか
- **台詞**: 載せずに設定だけ抜き出すのが基本
- **ほかの設定との関係**: 新しい設定が既存の設定の答えや前提になっていないか（例: 前日譚が「詳細不明」の理由を明かす）

選択肢の説明には、資料の該当箇所を引いて根拠を示す。作者の答えが選択肢と違う方向を示したら、それに従い、必要なら質問を立て直す。

## 4. 書く

- 先に `template.md` を読み、人物・用語の書式と置き場所に従う
- 「たぶん」「気がする」などのぼかした言い回しは、想像の余地として残す。断定形に直さない
- 書き換えは `scripts/replace_once.py` を使う。置き換え前の文字列が一度だけ現れることを確かめてから適用するので、意図しない箇所を書き換えない。定義ファイルは scratchpad に置く
- 星防省のように表記を統一した語は、取り込む文でもそろえる
- SS 側の誤字・表記揺れは設定資料で直さず、`ss_backlog.md` の「SS 側の修正候補」に回す

## 5. 確かめる

- 見出しを足した・変えたら `python3 scripts/toc.py on_sttings_materials.md` で目次を作り直す。extreme_world.md の目次は手で直す
- `git diff -U0 | grep '^-'` で、消えた行が意図したものだけか確かめる
- 目次に載る見出しが重なっていないか確かめる（2章の `####` 以下は重なってよい）
- 並べて置いた結果、新しい食い違いが生まれていないか見る（例: 舞台の年と誕生日から年齢が決まってしまう）。見つけたら作者に聞く

## 6. 報告する

- 章ごとに、何を足し、何を直したかを短くまとめる
- 作者の判断で書いた箇所と、資料から抜き出した箇所を分けて示す
- 書き方の決まりが新しくできたら、`template.md` への追記を提案する（書くのは了承を得てから）
- コミットと push は、頼まれるまでしない
